# Worker recovery iteration — 2026-11-09

Base PR #1 head 30d021d. Actions run 42595265881 succeeded for Ubuntu and Windows on Node 20 and 24. Reviewed the lock and privacy iteration notes, PR, source and tests. Chose stale-worker handling: the previous code treated any process-probe error or missing PID after 30 seconds as a dead worker and rewrote the job, potentially admitting overlapping work. A PID existence check is not an identity or descendant-process check; Node documents the basic signal-0 check at https://nodejs.org/api/process.html#processkillpid-signal.

Decision: do not automatically change queued/running records based on age or PID. They block submissions until completed or explicitly recovered offline. Invalid/unreadable matching job records now also block submissions rather than being silently ignored. README describes manual recovery and loss of retrievability after moving a stuck record; protect it because it may contain a prompt. This is deliberately conservative and means a crash, spawn failure or corrupt job may require manual intervention.

Validation: `npm run check` and `npm test`, Linux Node 24.22.1, 9/9 pass with simulated providers. Added old queued/running preservation and corrupt-record fail-closed tests; previous two-process test remains. CI must be checked on the new head. No live providers, Windows execution, account credentials or billing tested in this iteration.

Remaining: offline recovery is manual and requires a user to identify and stop detached worker and provider processes reliably; no full recovery UI or guaranteed process-tree cleanup. The queue can remain blocked after failed spawn. Some filesystem or malicious modification races and network filesystem behavior remain outside the one-task guarantee. Previous privacy work unlinks the answer file before saving the final result, leaving a crash/data-loss window; test and improve that next. Existing plaintext data, Windows ACLs, live provider behavior, provider terms for commercial use, client compatibility and marketplace packaging remain unresolved. No provider approval claimed.
